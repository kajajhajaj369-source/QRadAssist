## 2. API & Frontend Integration Verification

### 2.1 Demo-Blocking Issue Identified & Resolved
- **Issue:** Prior to audit, `src/api/app.py` did not serve static frontend assets at the root route (`/`), causing `http://localhost:8000/` to return a 404 HTTP error. Opening `index.html` via `file:///` caused browser CORS/network errors when fetching `/predict`, `/report`, `/labels`, and `/gradcam`.
- **Minimal Fix Applied:** Mounted `src/frontend` static files at `/` in `src/api/app.py` after all existing API routes, and added `_SRC_DIR` bootstrap to `sys.path`.
- **Verification:** `client.get("/")` returns HTTP 200 with `index.html`, and `style.css` and `script.js` resolve cleanly. Zero existing API routes or response contracts were altered.

### 2.2 Verified End-to-End Workflow Capabilities
1. **Upload X-Ray:** Frontend file input accepts `.png`, `.jpg`, and standard DICOM-exported images.
2. **Prediction Pipeline:** `/predict` accepts image uploads, performs deterministic grayscale/resize preprocessing, passes through DenseNet-121, and returns disease probabilities with single-sigmoid guarantee.
3. **Draft Report Generation:** `/report` synthesizes structured impressions and findings from predictions.
4. **Clinical Review Disclaimer:** Prominently rendered in both the frontend interface and draft report:
   > *"⚠️ Clinical Advisory: All reports generated by QRadAssist are AI-generated preliminary drafts intended exclusively for clinical decision support. They do not constitute a definitive medical diagnosis and must be reviewed and signed off by a qualified radiologist or clinician."*
5. **Grad-CAM Visualization:** `/gradcam` computes class-specific heatmaps on layer4 activations and renders a transparent red overlay directly onto the radiograph canvas.
